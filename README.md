# pymeasure

> **Status:** Obszerne drzewo projektu PyMeasure; pochodzenie i wkład własny wymagają porównania z upstream.

## Cel i rzeczywista zawartość

Repozytorium zawiera bibliotekę automatyzacji eksperymentów i sterowników aparatury, rozbudowaną dokumentację Sphinx, interfejsy graficzne, adaptery komunikacyjne, testy oraz konfigurację CI. Istniejący główny opis jest w `README.rst`.

## Zakres potwierdzony w repozytorium

- pakiet biblioteczny, duży katalog sterowników i dokumentacja API
- workflow CI, konfiguracje publikacji i pliki release
- testy, changelog, informacje o autorach i `CITATION.cff`
- licencja w `LICENSE.txt` i główny `README.rst`

## Gdzie leży wartość merytoryczna

- sam projekt PyMeasure ma wysoką wartość użytkową dla automatyzacji laboratoriów
- lokalna kopia może mieć wartość, jeśli zawiera własne sterowniki, poprawki lub eksperymenty nieobecne upstream

## Ograniczenia rzetelnej oceny

- na podstawie samego drzewa nie można przypisać autorowi repozytorium całej wartości dojrzałego projektu zewnętrznego
- rzetelna ocena wkładu wymaga porównania commitów z oficjalnym upstream PyMeasure
- ten `README.md` nie zastępuje kompletnej dokumentacji w `README.rst` i `docs`

## Jak zweryfikować wartość projektu

- ustalić źródłowy fork/tag i wykonać diff względem odpowiadającej wersji upstream
- wyodrębnić autorskie commity, sterowniki i poprawki
- oceniać osobno wartość projektu upstream oraz rzeczywisty wkład tego repozytorium
